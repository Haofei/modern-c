# Documentation map

Start here to decide which document to trust. The set of documents that
describe current intent is deliberately small; everything else is either a
reference generated from the code, an audit record, or rationale.

## Sources of truth

| Document | Role |
|---|---|
| [`../README.md`](../README.md) | Project overview, build commands, backend policy, validation gates. |
| [`todo.md`](todo.md) | The one roadmap: baseline gates, architecture goal, what is closed and what keeps it closed, active priorities, non-goals, patch rules. |
| [`typed-semantic-facts.md`](typed-semantic-facts.md) | How semantic information reaches the backends today, the sema-to-MIR handoff table, and the backend-import rule enforced by `zig build architecture-boundary-test`. |
| [`spec/MC_0.7_Final_Design.md`](spec/MC_0.7_Final_Design.md) | The normative language and backend contract. [`spec/README.md`](spec/README.md) explains the core / machine-contract / experimental / validation layering. |
| [`feature-maturity.json`](feature-maturity.json) | Machine-readable feature status and the backend policy. A feature is not core merely because the compiler accepts it. |
| [`backend-expected-failures.json`](backend-expected-failures.json) | The named known-gap list the `c-test` and `sweep` gates assert against. Entries only leave when the fixture genuinely passes. |

When one of these conflicts with an older document, the newer one wins unless
the code proves otherwise.

## Audit records

These record the result of a specific audit at the time it was run. Gates still
consult them, so they are kept current where a gate depends on them, but they
are not roadmaps.

| Document | Audit |
|---|---|
| [`unsafe-boundary.md`](unsafe-boundary.md) | The `unsafe` boundary, its markers, and the audited inventory of unsafe sites in `std/` (`tools/toolchain/mc-audit.sh --mode unsafe`). |
| [`c-ub-matrix.md`](c-ub-matrix.md) | How each C undefined-behavior class is forbidden, checked, or defined away in emitted C. |
| [`lowering-coverage.md`](lowering-coverage.md) | Function-level coverage of the lowering modules by the differential corpus (`zig build lowering-coverage`). |

## Historical records

Remediation notes, milestone drafts, migration ledgers, and experiment records
are kept in git history, not as live documents. The former
`refactoring-plan.md` is merged into `todo.md`; the former needle-count
inventory ledgers are described, and their replacement named, in
`typed-semantic-facts.md`.
